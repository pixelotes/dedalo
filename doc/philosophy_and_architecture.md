# Dédalo Philosophy and Architecture

## 1. Motivation and Starting Problem

In today's *workflow automation* ecosystem, tools such as **n8n**, **Node-RED**, **Apache Airflow**, or **Zapier** are the usual references. However, they suffer from serious problems when the goal is to deploy reliable automations on small servers, edge computing environments, or low-power boards such as a **Raspberry Pi 3B/4/Zero 2W**:

- **Massive RAM consumption**: A minimal instance of n8n or Node-RED frequently consumes between 350 MB and 1.2 GB of memory, often requiring Redis, PostgreSQL, and the Node.js V8 runtime.
- **Frontend packaging and overhead**: Thousands of npm packages in `node_modules`, vulnerable dependencies in the supply chain, and build processes that devour CPU.
- **Complex reactive engines**: They keep live graphs in memory, asynchronous event queues, and volatile state that make debugging difficult when something fails.

**Dédalo was born with a radical premise:**
> *What if a visual graph weren't an in-memory engine, but simply a graphical interface for compiling a deterministic, lightweight, flat Python script that uses less than 30 MB of RAM?*

## 2. Dédalo Design Principles

### 2.1. Compilation to Flat Code (`def run(ctx):`)
In Dédalo, the nodes and edges the user draws on the visual canvas are not evaluated by a graph interpreter at runtime. Instead, the compiler (`dedalo/compiler.py`):
1. Performs a **topological sort** of the directed acyclic graph (DAG).
2. Resolves dependencies and conditional branches.
3. Generates a pure Python source file in `data/flows/<name>.py` with a `run(ctx)` function.

```python
def run(ctx):
    # n1: input.rss
    n1 = runtime.rss(ctx, [], url="https://news.ycombinator.com/rss", max_items=10)
    # n2: transform.filter
    n2 = runtime.filter_items(ctx, [n1], contains="Python") if n1 is not SKIPPED else SKIPPED
    # n3: output.telegram
    n3 = runtime.telegram(ctx, [n2], chat_id="12345", secret="tg_token") if n2 is not SKIPPED else SKIPPED
    return {"n1": n1, "n2": n2, "n3": n3}
```

This approach offers immense advantages:
- **Native speed**: Execution is compiled Python code running at the direct performance of the CPython interpreter.
- **Full traceability**: You can open `data/flows/<name>.py`, read exactly what the flow does, debug it with `pdb`, or run it in isolation.
- **No hidden state**: The flow starts, executes its instructions, and finishes. Zero background memory leaks.

### 2.2. The Skip Sentinel (`SKIPPED`)
To manage control flow, conditions, and filters without introducing complex control structures or infinitely nested branches, Dédalo uses the **`SKIPPED`** sentinel object:
- If a node such as `transform.threshold` or `transform.filter` determines that the data does not meet the required condition, it does not raise an exception; it simply returns `SKIPPED`.
- The ternary expressions generated by the compiler propagate `SKIPPED` down the descendant branches at practically zero CPU cost.
- Terminal nodes are not executed and do not generate false alerts or unnecessary HTTP calls.

### 2.3. Zero-Dependency Frontend (Vanilla JS + Native SVG)
Dédalo's frontend lives in a single JavaScript file (`dedalo/static/dedalo.js`) and plain CSS:
- **No frameworks**: No React, Vue, Angular, or Svelte.
- **No bundlers**: Zero Webpack, Vite, Rollup, or npm. The browser downloads the static HTML and JS directly.
- **Infinite canvas in native SVG**: Cubic Bézier curve connections drawn by the browser's GPU, with zoom, drag, and real-time snapping at a steady 60 FPS.
- **Load time under 50 milliseconds**.

### 2.4. "Algorithm First, AI Only When It Adds Value" Philosophy
Many modern frameworks force the use of LLMs for mundane tasks (such as classifying a word or summarizing a paragraph), which introduces network latency, monetary costs, hallucinations, and excessive energy consumption.

Dédalo prioritizes deterministic algorithmic nodes:
- **Deduplication**: `transform.fuzzy_dedup` (Levenshtein/Jaro-Winkler algorithm, no LLM).
- **Summarization**: `transform.summarize` (classic Luhn, Luhn+, and TextRank algorithms).
- **Novelty detection**: `transform.diff` (SHA-256 hash computation stored in SQLite/disk).
- **Entity extraction**: `transform.regex` and `transform.html_extract` (CSS selectors).

Artificial Intelligence is reserved for tasks where non-deterministic reasoning is irreplaceable (root cause diagnosis with `transform.analyzer`, mitigation plans with `transform.planner`, or iterative coding with `transform.coder`).

```text
┌────────────────────────────────────────────────────────┐
│                      Web Browser                       │
│   (Vanilla JS + SVG Canvas + CSS Grid/Flexbox)         │
└───────────────────────────▲────────────────────────────┘
                            │ HTTP / JSON API
┌───────────────────────────▼────────────────────────────┐
│              FastAPI / Starlette Server                │
│  - /api/flows       - /api/catalog    - /api/secrets   │
│  - /api/run/{flow}  - /api/debug      - /api/export    │
├────────────────────────────────────────────────────────┤
│                    Dédalo Compiler                     │
│   (dedalo/compiler.py - TopoSort + Code Generation)    │
├────────────────────────────────────────────────────────┤
│                     Task Scheduler                     │
│   (dedalo/scheduler.py + cron.py - native cron, concurrent)│
├────────────────────────────────────────────────────────┤
│                      Node Runtime                      │
│   (dedalo/runtime.py - 64 modular functions)           │
├────────────────────────────────────────────────────────┤
│                       Data Store                       │
│  - data/flows/*.py (generated scripts)                 │
│  - data/secrets/*  (encrypted, 0600 files)             │
│  - data/master.key (encryption key, 0600)              │
│  - data/state/*    (diff state and persistence)        │
│  - data/history.db (SQLite audit)                      │
└────────────────────────────────────────────────────────┘
```

## 4. Security and Secrets Management

1. **Encrypted Secrets at Rest**:
   - Secrets (Jira tokens, mail credentials, API keys) are stored in `data/secrets/<name>.secret`, encrypted with Fernet (AES + HMAC) and written atomically with POSIX `0600` permissions (directory `0700`). Legacy plaintext files are still read and are encrypted automatically at startup.
   - The master key comes from `DEDALO_MASTER_KEY` or `DEDALO_MASTER_KEY_FILE`; if neither is set, `data/master.key` is generated (`0600`). The generated key only protects against partial copies of `data/`; keep the key outside `data/` for real protection.
   - Alternatively, secrets can be injected as `DEDALO_SECRET_<NAME>` environment variables (never written to disk). A secret file may also hold a reference (`op://...`, `vault://...`) resolved on demand and cached in memory only, so no value is stored locally; see [external_secrets_evaluation.md](external_secrets_evaluation.md).
2. **No Leaks in the Compiled Code**:
   - The compiler never writes credential values into the generated `.py` files.
   - The code is generated with `secret="secret_name"`, and at runtime the runtime invokes `dedalo.secrets.get("secret_name")`, resolving it in volatile memory.
3. **Dynamic Telemetry Masking**:
   - Nodes such as `transform.analyzer` have the `sanitize_secrets: True` parameter, which applies prior regular expressions to obfuscate JWT tokens, Bearer tokens, RSA private keys, and passwords before any text leaves for an LLM or third-party service.
4. **Network Perimeter of the API** (no authentication by design, so keep it on localhost or a trusted network):
   - No CORS. The `Host` header is validated against `DEDALO_ALLOWED_HOSTS` (default: localhost only) to stop DNS rebinding, and state-changing requests whose `Origin` differs from `Host` are rejected (CSRF).
   - Every response carries a strict `Content-Security-Policy`, `X-Frame-Options: DENY`, `nosniff` and `Referrer-Policy`; request bodies are limited to `DEDALO_MAX_BODY_MB` (25 MB by default).
   - Webhooks accept an optional shared token (`DEDALO_WEBHOOK_TOKEN`) that never reaches the flow or the history.
5. **Shell Execution Hardening**:
   - Subprocesses started by `input.command`, `output.command` and the `bash` tool of `transform.coder` do not inherit Dédalo's secrets from the environment (`DEDALO_SECRET_*`, `DEDALO_MASTER_KEY*`, `DEDALO_LLM_KEY`, `DEDALO_TELEGRAM_*`; extend with `DEDALO_ENV_DENY`).
   - Optional isolation with bubblewrap (`DEDALO_SANDBOX=off|auto|on`, per-node `sandbox` option): read-only `/usr` and `/etc`, empty `/tmp`, only the working directory writable, `data/` hidden.
